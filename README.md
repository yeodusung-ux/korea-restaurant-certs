# 좋은 음식점 통합 조회

음식점 **인증·선정 8종**을 한 화면에서 지역·음식유형으로 찾아보는 도구입니다.
페이지 하나로 끝나며 서버가 없습니다(정적 HTML).

👉 **https://yeodusung-ux.github.io/korea-restaurant-certs/**

| 인증 | 무엇을 보증하나 | 소관 |
|---|---|---|
| 모범음식점 | 위생 | 행정안전부 |
| 착한가격업소 | 가격(메뉴·가격 공개) | 행정안전부 |
| 백년가게 | 업력(오래된 점포) | 소상공인시장진흥공단 |
| 안심식당 | 방역·위생 수칙 | 농림축산식품부 |
| 관광공사 맛집 | 관광 콘텐츠 선정(사진·대표메뉴·영업시간) | 한국관광공사 |
| 식품안심업소 | 위생 인증(구 위생등급제) | 식품의약품안전처 |
| 파란인증 | 직접 다녀보고 고른 곳 | 개인 선별 **⚠️비공식** |
| 빨간인증 | 직접 다녀보고 고른 곳 | 개인 선별 **⚠️비공식** |

> ⚠️ **앞의 여섯은 공공데이터, 뒤의 둘은 개인이 직접 고른 목록**으로 성격이 다릅니다 —
> [직접 선별 2종](#직접-선별-2종--파란인증빨간인증) 을 읽으세요.

## 기능

- **★ 별점** — 받은 인증 수만큼 별. 기본 정렬이 별점 높은순이고, 이때는 같은 가게를 한 줄로 접는다
- 인증 칩을 켜고 끄면 **하나라도 해당하는 곳**을 보여준다(교집합 모드는 2026-08-09 제거 — 별점이 그 역할을 대신한다)
- 지역 **시도 → 시·군 → 구** 3단계, 음식 대분류 **다중 선택**, 원본 분류,
  통합검색(업소명·주소·메뉴 + **내 목록에 적어 둔 메모**)
- 지역 × 음식유형 교차표(숫자 클릭 → 해당 목록)
- 결과 CSV 내보내기 · 주소 클릭 시 지도 검색 · 폰 대응(카드 레이아웃)

## 직접 선별 2종 — 파란인증·빨간인증

**공식 제도가 아닙니다.** 직접 다녀보고 고른 곳을 모은 개인 목록이며, 이름은 화면의 칩 색과
맞췄습니다(파란인증=파랑 칩, 빨간인증=빨강 칩). 공공 API 가 없으니 나머지 여섯과 달리
자동 수집하지 않고, **네이버 지도 즐겨찾기로 관리하는 목록**을 CSV 로 굳혀 리포에 커밋합니다.

```bash
python build/make_guide_csv.py 파란.json build/guide_blue.csv
python build/make_guide_csv.py 빨간.json build/guide_red.csv
```

즐겨찾기 JSON 을 받는 방법은 `build/make_guide_csv.py` 파일 첫머리에 적어 두었습니다.
갱신하려면 위 명령을 다시 돌리고 CSV 를 커밋하면 됩니다(워크플로가 다음 실행에서 반영).

한계 — **알고 쓰세요.**

- **자동 갱신되지 않습니다.** CSV 를 다시 만들기 전까지 그대로입니다.
- **전화번호·지정일이 없습니다.** 즐겨찾기에 그 정보가 없습니다. 그래서 동일 가게 매칭도
  전화번호를 못 쓰고 `주소 + 상호 유사`만으로 붙습니다(실측 결합률 파란 48% · 빨강 45%).
- 대분류는 즐겨찾기의 `카페`/`BAR` 만 그대로 쓰고 `음식점`은 상호로 추정합니다.
- 개인 취향이 반영된 목록이라 **공공 6종과 같은 객관적 근거가 없습니다.** ★별점에는 함께
  들어가므로, 별이 많다고 공적으로 검증된 곳이라는 뜻은 아닙니다.

## 자동 갱신

`.github/workflows/update.yml` 이 **매주 일요일 04:00(KST)** 에 원본을 다시 받아 `index.html` 을 새로 만듭니다.
데이터가 그대로면 커밋하지 않습니다. Actions 탭에서 수동 실행(`Run workflow`)도 됩니다.
민간 가이드 2종은 네트워크를 타지 않고 위의 시드 CSV 를 읽습니다.

### 필요한 시크릿 2개

리포 **Settings → Secrets and variables → Actions → New repository secret**

| 이름 | 발급처 | 쓰이는 곳 |
|---|---|---|
| `ODCLOUD_KEY` | [공공데이터포털](https://www.data.go.kr) 일반 인증키(Decoding) | 백년가게 · **관광공사**(같은 키, 활용신청만 별도) |
| `MAFRA_KEY` | [농림축산식품 공공데이터 포털](https://data.mafra.go.kr) — 가입 시 자동 발급 | 안심식당 |
| `MFDS_KEY` | [식품안전나라](https://www.foodsafetykorea.go.kr/api/) — 가입 시 자동 발급 | 식품안심업소 |

> ⚠️ data.go.kr 개발계정 키는 **1년 만료**입니다. 만료되면 워크플로가 실패하며 메일로 알려줍니다.

### 실패하면 사이트는 어떻게 되나

**직전 정상본이 그대로 유지됩니다.** 빌드 스크립트는 소스별 최소 건수를 검사해
하나라도 미달이면 예외를 던지고 `index.html` 을 건드리지 않습니다.
한 소스가 조용히 비어 수만 건이 사라진 페이지가 배포되는 것을 막기 위한 장치입니다.

## 로컬에서 돌려보기

```bash
export ODCLOUD_KEY=...
export MAFRA_KEY=...
python build/build_site.py      # → index.html 생성 (약 2분)
```

의존성 없음(파이썬 표준 라이브러리만). Python 3.8 이상.


## 데이터를 다루며 알게 된 것

원본 4종은 분류 체계도 지역 표기도 제각각이라 그대로 합칠 수 없었습니다. 코드에 반영된 보정들:

- **착한가격업소 다운로드 주소가 갱신마다 바뀝니다.** `atchFileId` 가 파일 버전에 묶여 있어
  매번 데이터셋 페이지에서 새로 찾습니다. 고정 URL로 박아두면 분기 갱신 때 옛 파일을 받습니다.
- **안심식당 `RELAX_SI_NM` 은 시도, `RELAX_SIDO_NM` 은 시군구**입니다(이름과 반대).
  `USE_YN` 에는 `Y`/`N` 말고 `여` 가 5건 섞여 있어 유효로 처리합니다.
- **시군구 세밀도가 달랐습니다.** `성남시 분당구`(모범음식점·백년가게) vs `성남시`(나머지) 라
  그대로 두면 교차 조회가 갈라집니다 → **시/군 레벨로 통일**. 구 단위는 검색으로 좁힙니다.
- **`전남광주통합특별시`** 표기는 시군구를 보고 광주광역시/전라남도로 되분리합니다.
- **주소 문자열의 시도 표기는 지도에 그대로 넘기면 안 됩니다.** `전남광주통합특별시` 6,111건은
  지도 서비스가 아는 이름이 아니고, `광주광역시광역시`·`부산광역시시`·`경상북포`·`전북틀별자치도`,
  `강원특별자치도원주시`처럼 시군구가 붙어버린 것, 약칭(`강원`·`경북`) 7,483건이 섞여 있습니다.
  그래서 지도 링크는 주소 앞머리를 떼고 **정규화해 둔 시도·시군구로 다시 조립**합니다.
  다만 `세종대로`처럼 **도로명이 시도명으로 시작**하면 건드리지 않습니다(뒤에 `로`/`길`이 붙으면 제외).
- **백년가게 최신 API본은 컬럼이 4개뿐이고 연락처가 전량 비어** 있어, 2022 파일본에서
  업종·연락처를 이식합니다(약 75% 매칭). 이때 **시도·시군구가 맞을 때만** 붙입니다 —
  이름만 보고 붙이면 서울 가게에 지방 가게 정보가 들어갑니다.
- **대분류는 추정값**입니다. 안심식당(6종)·착한가격업소(11종)는 원본이 열거형이라 그대로 매핑하지만,
  모범음식점(233종)·백년가게(782종)는 자유입력이라 키워드 규칙을 씁니다. 원본 값은 항상 별도 열로 남깁니다.
- **관광공사는 하루 1,000콜 한도**라 목록(14콜)만 매주 전량 갱신하고,
  대표메뉴·영업시간(종목당 1콜, 13,521건)은 **매 실행 900건씩 캐시에 점진 축적**한다
  (`build/tour_cache.json`, 약 14주에 완성). 캐시를 커밋하지 않으면 매주 처음부터 시작한다.
- **식품안심업소만 유효기간이 있다**(`ASGN_TO`). 실측에서 스타벅스 선릉로점이 당일 만료였다 —
  만료·지정취소·폐업 3중 필터를 매 빌드마다 다시 계산한다. 또 본사 일괄신청이라 프랜차이즈가 43%여서
  (메가커피 1,126·스타벅스 960) **일반음식점만 + 같은 상호 5곳 이상 제외**로 좁혔다(37,996 → 11,408).
- **동일 가게 매칭**(별점 계산의 근거)은 근거가 강한 둘만 씁니다 — ① 전화번호 ② 시군구+도로명+건물번호 **AND 상호 유사**.
  `시군구+상호` 만으로 묶으면 동명이점(진미식당·김밥천국)이 한 가게가 됩니다.
  다만 **주소만 같은 건물 안의 서로 다른 식당이 한 그룹으로 묶이는 경우가 남아 있습니다**
  (호텔 입점 식당 등). 별점이 실제보다 커 보일 수 있는 알려진 한계입니다.
- **네이버 즐겨찾기 주소는 표기가 다릅니다.** 시도가 약칭(`서울 중구 …`)이고 광주·전남이
  `전남광주` 한 덩어리로 옵니다(실측 12건) — 공공데이터의 `전남광주통합특별시` 와 같은 병이라
  같은 규칙으로 되분리합니다. 세종은 시군구 자리에 읍·면이 옵니다(`세종 전동면 고산길 71`).
  그래서 시드를 읽을 때 **시도를 전체이름으로 펴서 주소 문자열까지 다시 조립**합니다 —
  구(區) 추출과 지도 질의 정규화가 그 표기를 전제하기 때문입니다.
- **메모 검색은 정적 인덱스에 못 넣습니다.** 메모는 브라우저 localStorage 라 빌드 때 굳는
  `SEARCH` 문자열에 들어갈 수 없습니다. 검색할 때마다 전 행의 `favKey` 를 만들면 9.3만 행
  정규식이 타건마다 도니, **`favKey→행` 역인덱스를 한 번만 만들고**(메모가 하나라도 있을 때만)
  메모가 바뀔 때 `favs` 쪽만 훑어 `MEMO` 배열을 다시 칠합니다(실측 재구축 82ms · 검색 9ms).
